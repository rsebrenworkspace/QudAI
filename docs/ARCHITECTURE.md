## 2. IPC protocol

Exchange directory: `%USERPROFILE%\AppData\LocalLow\Freehold Games\CavesOfQud\QudAI`, named in one place per language: `qudai_config.py` for Python (`brain.py`, `twitch_bot.py` and the console import it) and `ExchangeDir` in `AIBrainPart.cs` (built from the user profile; the mod cannot import Python). No user name is in the source (Test 132). `qudai_config.py` honors the environment variable `QUDAI_EXCHANGE_DIR` first (the test suite points it at a temp folder so tests can never touch the real game files), and `QUDAI_LM_URL` replaces the LM Studio endpoint (tests use a dead port for deterministic, offline runs). `active.flag` is removed only when the brain is **launched** (`remove_stale_flag()` in `main()`), never at import.

| File | Direction | Notes |
|---|---|---|
| `state.json` | game -> Python | Written once per player turn (temp file + move). Python deletes it after a successful parse. |
| `action.json` | Python -> game | `{"action": "...", "reason": "..."}`. C# polls up to 6000 ms, then passes a turn. |
| `active.flag` | both | Existence = AI engaged. Deleting it restores manual control. |
| `death.json` | game -> Python | Written once on player death; consumed by the Chronicler. |
| `last_state.json` | Python | Debug copy of the last state. |
| `last_action_executed.txt` | C# | UTC timestamp + action. Useful to tell "hung" from "looping". |
| `mutation_ranking.txt` | Python -> game | Mutation names, best first (class or display names; `#` comments). Rewritten when the detected build changes; read (cached by file time) by the mutation picker. |
| `memory/decision_trace.jsonl` | Python | One JSON line per turn: turn clock, zone, position, action, reason (160 chars), combat flag, engine flags (`autoexplore_stuck`, `zone_fully_explored`, `unexplored_cells`, nearest unexplored, `reachable_edges`), chosen exit, whether exits are suppressed, last-move-failed. Rotates at 3 MB to `.1`. For diagnosing loops without pasted console output; not committed. |
| `memory/exit_choices.jsonl` | Python | One JSON line per zone-exit decision (zone, position, `reachable_edges`, reverse direction, failed/explored/cycle neighbours, candidates, novel candidates, chosen, mode). Diagnostic and future training data; not committed. |

Known protocol weaknesses (see HANDOFF): non-atomic `action.json` write, no turn id, timeouts that can race.

## 3. Turn flow

1. `XRLCore.PlayerTurn` prefix runs. If `active.flag` is absent, vanilla turn runs.
2. C# exports `state.json`, blocks waiting for `action.json`, executes it via `ExecuteCommand`.
3. Python (`main()`): parse state, update zone/stair/companion memory, compute `took_damage`, run `query_decision`,
   then the loop breakers, then write `action.json`.

### Decision pipeline (`query_decision`)

Combat mode (`is_in_combat`) = damage taken, an adjacent threat, or `get_close_threats` (enemy within 6 tiles, or 10 with `hostiles_nearby`; a non-adjacent enemy with `has_los: false` does not count, T-1.11).

Pre-checks: zone/stair records, stuck-autoexplore ingestion, template detection (every turn, see Known Issues),
emergency retreat to stairs up (underground, low HP), priority AP spend.

**Phase A: safe mode** (`not is_in_combat`), in order:
1. Autolevel (Twitch winner, else template doctrine)
2. Sustenance: butcher/harvest adjacent sources (with a 3-in-a-row cool-down), then hunger: `EAT` if he has food (no camp/cook detour, no free meal), then 2C foraging: when hungry or carrying fewer than 3 food items, `choose_food_source` walks to the nearest `food_sources` corpse (needs Butchery) or plant (needs Harvestry) with `NAVIGATE_TO_CELL`, with a pursuit time-out and a blacklist for unreachable targets (T-1.13)
3. Rest (HP < 75%, not swimming)
4. Ammo top-off; 4B. companion recruitment
5. Stairs/delving (surface needs level gate; underground is bold if HP >= 70%). After an emergency retreat from underground (low HP, or an "Impossible" creature in view even at full HP) `RETREAT_TARGET_LEVEL = level + 1` locks out further descent until that level is reached, regardless of HP (T-1.22)
6. Inward border steer (arrival grace only: first ~4 `ZONE_STEP_COUNT` on a border tile; the zone-hopping flag no longer extends it, T-1.16)
7. Native `AUTOEXPLORE` (unless stuck/explored/swimming). When autoexplore is stuck and C# reports `frontier_checked`, step 8 navigates (`NAVIGATE_TO_CELL`, committed via `FRONTIER_COMMIT`) to the nearest engine-reachable `frontier_targets` entry instead of the centroid of all unrevealed cells; none reachable with exits reachable means the engine says only rock is left (zone remembered as explored). A frontier target is written off (with neighbours within 2 tiles) after 3 failed approaches or 60 turns without arriving (`FRONTIER_FAILS`, `FRONTIER_PURSUIT`, `FRONTIER_BAD`, T-1.20), because the engine can list a target as reachable while the real step keeps failing
8. Macro-sector navigation across water/obstacles (not in towns)
9. Local unvisited frontier
10. Zone-exit transition (committed exit)
11. `NAVIGATE_ZONE_EXIT` via engine pathfinder
12. Least-visited fallback

**Phase B: tactical LLM** (combat only): LM Studio at `localhost:1234`, 6 s timeout, strict JSON, choices from a labeled
VALID ACTIONS list, ancestral wisdom prepended to the system prompt.

**Phase C: deterministic fallback** by archetype: melee, esper, gunslinger, nomad.

### Loop breakers (`main()`)

Exit-thrash breaker (`note_exit_failure`, T-1.17): every exit failure is blacklisted and counted; 4 failures in a zone suppress exit selection for 60 turns (`TURN_CLOCK`) so Phase A explores instead; an empty `reachable_edges` never wipes the blacklist. A committed frontier walk (`is_frontier_walk`: `NAVIGATE_TO_CELL` with a "Frontier:" reason) is exempt from the oscillation breaker (T-1.21). Companion-block guard (`guard_companion_blocked_burrow`, applied to the final action in `main()`): a burrow (`ATTACK_WALL`) is replaced by swap, swap, wait cycles when the only exit is occupied by a companion (T-1.17). Stationary-repeat breaker; oscillation breaker (positions window of 24, entropy rule: >=10 samples with <=5 unique);
combat actions are exempt. Zone-hopping breaker (2-, 3-, 4-cycles) in `update_zone_records`.
Autolevel circuit breaker keyed on `(ap, sp, mp, len(skills))`.

## 5. Commands (`action.json`)

<!-- actions:start -->
- `WAIT`: pass a turn
- `AUTOEXPLORE`: native autoexplore step (also picks up safe loot)
- `RELOAD`
- `FIRE_MISSILE@x,y`: single shot, sweep/rapid forced to 0, LOS + companion ray-trace checked
- `THROW_ITEM@x,y`: throws the first thrown weapon (`GameObject.GetFirstThrownWeapon`) at a hostile creature in that cell with the engine's `PerformThrow`; refuses, and reports why in `last_throw`, with no thrown weapon, no hostile in the cell, a companion in the cell or on the line (R8), no line of sight, out of range (`GetBaseThrowRange`) or in a peaceful settlement (R7); costs a turn (R4)
- `ATTACK_WALL:<dir>` (aliases `FORCE_ATTACK:`, `ATTACK_CELL:`): melee a destructible obstacle; refused in settlements
- `USE_STAIRS_DOWN`, `USE_STAIRS_UP`
- `GET_ITEM`
- `DROP_ITEMS:<id>,<id>` (up to 5 whole items by object id): takes each out of the pack and puts it on the player's cell with `DroppedByPlayer` set (so autoget never re-takes it); refuses equipped items, settlements and hostiles nearby; verifies each item left the pack and gives it back if the drop failed. `EQUIP_ITEM:<id>`: the engine's `AutoEquip(item, forced)`. Both cost a turn and report in `last_inventory_action`.
- `EXAMINE_ITEM:<id>` (BACKLOG B15 stage 1, issue 102, Test 126): runs the engine's own **Examine** inventory action on one item in the pack (`InventoryActionEvent.Check(... "Examine" ...)`, energy charged by the loop, not by the event); refuses when hostiles are near or when the Sifrah minigame option is on (`Options.SifrahExamine`); reports `last_inventory_action` kind `examine` with `ok` entries `id|name after|outcome` (outcome `understood`, `partial`, `partial again`, `unchanged` or `gone`) and `failed` entries `id:reason`
- `TAKE_ITEM:<id>` (BACKLOG B16, issue 96, Test 120): takes ONE unowned, takeable armor, weapon or shield by object id from the player's cell or an adjacent one (`TakeObject`, `ExecuteTakeItem`); refuses settlements, hostiles nearby, anything owned, anything the player dropped (`DroppedByPlayer`) or the loot step gave up on, and anything over the weight limit; reports `last_inventory_action` kind `take`. It does not equip: Python decides, and the existing `EQUIP_ITEM` wears it
- `LOOT`: takes one unowned ground item, or empties one unowned chest, on his cell or an adjacent one (`TryLootNearby`); never in a settlement, never with hostiles nearby, at most 80 actions per zone; the same step also runs at the start of every `AUTOEXPLORE` turn
- `EAT`, `MAKE_CAMP`, `COOK_MEAL`, `BUTCHER`, `HARVEST`: programmatic, no UI modals
- `AUTOLEVEL`, `AUTOLEVEL_STAT:<stat>`, `AUTOLEVEL_SKILL:<class>`, `AUTOLEVEL_MUTATION:<name>`, `AUTOLEVEL_BUY_MUTATION[:<name>]`
- `REST`, `PASS`: pass a turn; they no longer spend AP/SP/MP (the old hard-coded C# autolevel ignored the template, T-1.24)
- `USE_ABILITY:<command>[:<dir>]`: alias-resolved against the player's ActivatedAbilities
- `ACTIVATE_SPRINT`, `SPRINT_<dir>`
- `NAVIGATE_TO_CELL:x,y`: engine A* (`AutoAct.TryFindPathStep`); if the next step is blocked by a solid, ownerless, non-creature object with hit points (a tree, a plant wall) it is attacked (`TryBreakPathObstacle`, reported in `last_burrow`), because the engine routes through such obstacles
- `NAVIGATE_ZONE_EXIT:<N|S|E|W>`: engine edge pathfinding (`AutoAct.TryFindEdgeStep`)
- `MOVE_<dir>`

## 6. `state.json` fields (grouped)

- **Vitals/progress:** `hp`, `max_hp`, `level`, `xp`, `ap`, `sp`, `mp`, `attributes`, `av`, `dv` (the engine's current armour and dodge values), `melee` (`weapon`, `damage` dice, `penetration` from `MeleeWeapon.GetNormalPenetration`, `hit_bonus` of the main hand; empty `damage` when the read failed), `skills` (class and display name),
  `learnable_skills` (only affordable ones), `mutations` (`level`, `cap`, `can_level`)
- **Position:** `x`, `y`, `z`, `zone_id`, `zone_name`, `is_settlement`, `zone_tier`
- **Ability use:** `last_ability_use` (result of the last `USE_ABILITY`: `seq`, `command`, `dir`, `known`, `cd_before`, `cd_after`, `fired` = the cooldown rose, or the ability label changed ("Lase (5 charges)" count, toggle on/off), `refused` + `reason` when the C# pre-check found the ability disabled, unusable or on cooldown, or `null`). Python `note_ability_use` counts it per command in `memory/ability_stats.json` (`attempts`, `fired`, `refused`), kept across characters. Abilities are matched by exact engine command through `data/ability_families.json` (loader `ability_registry.py`); an ability in no wired family is never used automatically (T-1.25).
- **Stationary hostiles (T-1.31):** `is_ignorable_stationary_enemy` ignores a stationary Easy-or-weaker hostile at distance 2 or more (it was 4 or more); adjacent, Tough+, turrets and damage taken still force combat.
- **Autolevel breaker (T-1.30):** `AutolevelBreaker` (used by `main`): two AUTOLEVEL decisions in a row with unchanged `(AP, SP, MP, skills)` suppress autolevel; it retries after `AUTOLEVEL_RETRY_TURNS` (100) instead of waiting for a level-up.
- **Model lab (T-1.41):** `tools/model_lab.py` + `data/model_lab_scenarios.json` replay fixed combat situations through `query_llm_decision` for each LM Studio model and score parse, menu and policy results, latency and VRAM (docs/MODEL_LAB.md). `brain.LLM_PROBE` (normally `None`) is a hook the lab sets to a dict so the function records the offered menu, the raw reply, the latency and the parsed action; it has no effect on a normal run.
- **Items (T-1.43):** `data/items.json` (built from `ObjectBlueprints/*.xml`, ancestry resolved; 974 loot items, see docs/ITEM_SCORES.md) feeds `item_scoring.py`: `build_profile(template)` derives a build's weapon skills, caster/ranged/shield flags, stat priorities and weight class from the template; `score_item(item, profile)` returns `(score, keep_value, reasons)` from the item's armor/weapon/boost stats (no name matching); `choose_equips(inventory, profile)` fills empty slots and replaces only clear upgrades (`DOMINATED_MARGIN`); `choose_drops(inventory, profile, carried_weight, capacity, hungry)` drops outclassed gear and over-cap stacks always, and other junk only under weight pressure (`BURDEN_DROP_RATIO`) and only as much as needed; never equipped, quest, artifact, escape, unidentified, weightless, the sole light source or the sole firearm of a firing build. **Not wired yet:** the mod does not export the inventory, and there is no drop or equip command: the functions are pure and tested (Test 87) but unused by `brain.py`.
- **Pacing (HANDOFF issue 99, Test 124):** after writing an action the loop sleeps `EXPLORE_STEP_DELAY` (default 0.10 s, env `QUDAI_EXPLORE_DELAY`) on a non-combat turn or `COMBAT_STEP_DELAY` (0.20 s, env `QUDAI_COMBAT_DELAY`) in combat; both are clamped to 0 to 5 s. The loop only acts on a fresh `state.json` (deleted after it is read), so the pause is added latency, not a synchronisation point. Measured before the change `[verified in the traces, 1,600 exploration turns, 2026-10-09]`: 0.30 s per exploration turn (0.25 of it this sleep), about 3.2 s per turn that calls the model.
- **Combat call settings (T-1.42):** `QUDAI_LLM_MAX_TOKENS` (default 128) and `QUDAI_LLM_EXTRA` (JSON merged into the request, e.g. `{"reasoning_effort": "none"}` to switch a thinking model's reasoning off in LM Studio) are read at start-up into `LM_MAX_TOKENS` and `LM_EXTRA_PAYLOAD`. The lab sets the same two values from `--max-tokens` and `--extra`.
- **Model selection (T-1.40):** `detect_lm_studio_model` uses `pick_model_id`: the env override `QUDAI_LM_MODEL`, else a model LM Studio reports as `loaded` (type `llm` or `vlm`, from `/api/v0/models`), else the first non-embedding model of `/v1/models`. `QUDAI_LLM_TIMEOUT` (seconds, default 6) is the combat call timeout. The model id is written to every decision-trace row (`model`) and to the post-mortem.
- **Danger ledger (T-1.39):** `danger_ledger.py` keeps `memory/danger_ledger.json` per creature blueprint: hits, the largest single-turn HP loss seen while exactly one kind of hostile was adjacent (not on fire, bleeding or poisoned), total damage, and kills (credited at death to the adjacent hostile named in the death message). `brain.py` records damage each turn and the kill at death. `danger_ledger.apply` runs on the enemy list right after `filter_hostile_enemies` and raises the `difficulty` of a creature whose largest hit was at least 35% (Very Tough) or 60% (Impossible) of the CURRENT max HP, once it has two hits or a kill; the engine rating is kept in `difficulty_engine`. It never lowers a rating, so every rule that reads `difficulty` (stand-and-fight limit, `is_overwhelmed`, danger retreat) and the LLM prompt use it.
- **Post-mortem (T-1.38):** `chronicler.process_death_event` also calls `postmortem.write_postmortem`, which writes `chronicles/Postmortem_Gen<n>_<name>_<ts>.md` from the decision trace (`postmortem.load_trace_run`: the newest run only) and `last_state.json`: the hostiles in view with the engine rating, level and line of sight, the companions, ability cooldowns, the last 25 turns of HP and decisions with reasons, the decision mix, and rule-based observations (largest HP loss, damage right after fleeing, REST in combat, a position flip, one ability repeated). No language model is involved. The brain passes `last_state` and the trace path.
- **Ancestral lessons (T-1.37):** `chronicler.process_death_event` still saves a one-line model-written lesson per death in `memory/ancestral_wisdom.json`, but it starts `approved: false`. Only `approved: true` lessons (most recent 4) are injected into the combat prompt by `format_ancestral_memory_for_prompt`. `python tools/wisdom.py` lists them, `approve <gen>` and `reject <gen>` change the flag (nothing is ever deleted).
- **Danger retreat (T-1.36):** `border_retreat_decision` (right after the stairs-up retreat): an Impossible hostile in line of sight within 10 tiles while he is within `BORDER_RETREAT_RADIUS` (6) of the border he arrived by (`LAST_ZONE_ENTRY`) sends him back through it (`MOVE_<rev>` on the border, else `NAVIGATE_ZONE_EXIT:<rev>`), and the exit that leads into that zone goes into `FAILED_ZONE_EXITS`. The decision carries `flee_ok`, which `enforce_stand_and_fight` respects. Logged as `[DANGER RETREAT]`.
- **Console Lab tab (T-1.56, BACKLOG B13 stage 1, HANDOFF issue 82):** scenario cards for the game's wish prompt (Ctrl+W), from `data/wish_scenarios.json`: why, set-up steps, the wish lines with a confidence tag (`documented` in `WishCommands.xml` or `named` in the engine's handler with the effect not read), what to watch for and which test it covers. Buttons copy the wish lines to the clipboard and log "scenario used" to `memory/lab_runs.jsonl`; a level box turns a target level into the exact `xp:N` wish from the current XP and the game's curve (`xp_for_level`, ENGINE_INTERNALS 14.16). Cards only: nothing here talks to the game (Test 101 checks every `spawn:` and `item:` names a real blueprint in the catalogs).
- **Prompt tokens in the trace (HANDOFF issue 86):** each model call stores `usage` (`prompt_tokens`, `completion_tokens`) and the loaded context window (LM Studio's `/api/v0/models`, `loaded_context_length`, read when the model is detected) in `LAST_LLM_USAGE`; a trace row written on a turn with a model call carries them as `llm`. The console's Mod health tab shows the largest and p95 prompt against the window and warns above 60 percent (Test 107).
- **Zone danger and exit steering (B10 step 1, HANDOFF issue 85):** `zone_danger.py` (pure) keeps a `Ledger` of zones where a mobile hostile out of our class was seen: the engine called it Very Tough or Impossible, or the catalogue threat ratio is 3 or more, or three or more hostiles together add up to 3 (`brain.note_zone_danger`, prints `[ZONE DANGER]`). The two ratio-based triggers apply only to a character with no ranged opener (`has_ranged_opener`: an ability in lase, stunning_force, a ray, sunder_mind, teleport_other or syphon_vim, ready or not, or a missile weapon), because the ratio models the main hand only (Test 109); the engine's difficulty always counts. A flag lapses when our level reaches the creature's level minus 3 (capped at six levels above the level it was seen at), and in any case two levels after it was raised. `get_zone_exit_target` asks `zone_danger.steer` once it has its candidate exits: with an active flag it narrows the choice to the exits whose neighbouring zone has the least danger pressure (`sum of 1 / (1 + distance)` over flags on the same depth), and when the danger is close and no exit ahead is better than standing here it picks the way it came (`[ZONE DANGER] Backtracking`, exit log `mode: danger_retreat`). **Last-seen memory:** the flag also keeps the cell where the creature was last in view (`Ledger.seen`, `avoid_points`); `pick_frontier_target` skips frontier targets within `AVOID_RADIUS` (8 cells) of it for `AVOID_MAX_AGE` (80) turns after it was seen, drops a committed target that lies near it, and offers none when every target is near (Test 110). It only changes which exit is picked: the engine's reachable edges, `FAILED_ZONE_EXITS`, the stairs and the border retreat are untouched. In memory only (a brain restart forgets it). Test 106, which includes a 14-step walk (no oscillation, no flagged zone entered).
- **Creature threat score (B12 stage 2, HANDOFF issue 84):** `creature_threat.py` looks a creature up in `data/creatures.json` by blueprint or by display name (longest trailing words, so "wet chitinous puma" finds the puma) and scores a race: turns we need to kill it against turns it needs to kill us, with live hit points when the state has them. The console threat strip shows the class (`~deadly`) beside the engine difficulty. **Display only: the brain does not read it.** It uses the state's own `av` and `melee` when present (the engine's rule against the creature's catalogue AV) and falls back to a guess without them (Test 104). `data/parties.json` (built by `tools/build_party_table.py` from `PopulationTables.xml`) gives the expected size of every game party table, and `party_threat` scores a whole party (at most `MAX_ENGAGED` attack at once; Test 105). The constants are guesses until `tools/threat_calibration.py` (ranks the recorded deaths) says otherwise (Test 103).
- **Creature catalog (T-1.55, BACKLOG B12 stage 1, HANDOFF issue 81):** `tools/build_creature_catalog.py` (reusing the item catalog's blueprint loader and inheritance resolver) writes `data/creatures.json` (it applies `<mixin>` blueprints, `MixinCatalog`, Test 108): 852 concrete creature blueprints with level (fixed, range, or formula), hit points, stats, natural melee attacks (removed ones dropped), ranged weapons, mutations, skills, flags (turret, swarmer, robot, mental_shield, plant, hero_capable...), `rooted`, `is_ranged`, `calm` (Brain `Calm="True"`: does not start fights), factions, `start_rep` (the lowest `InitialPlayerReputation` of its factions in `Factions.xml`) and `likely_hostile` (`start_rep` at or below -250, inferred). `tools/creature_report.py` writes `docs/CREATURES.md`. Static facts for planning; the live export stays the truth (R3). Nothing in the brain reads it yet (Test 100).
- **Proselytize outcome log (T-1.54, BACKLOG B11 stage 1, HANDOFF issue 80):** `record_proselytize_attempt(action, game_state)` (called where the final action is committed) notes every `USE_ABILITY:CommandProselytize` with the target it was aimed at (`proselytize_target`: the nearest listed creature in that direction), its level, difficulty and hostility, our level, Ego and HP and the companions before; `note_proselytize` (each turn) resolves it from the companion list within two looks as `recruited` or `not_recruited` (with `gap` = target level minus ours and `fired` from the ability cooldown), or `unresolved` if another attempt overtakes it, writes one line to `memory/proselytize_log.jsonl` and prints `[PROSELYTIZE] ...`. `tools/proselytize_report.py` prints the odds by level gap and by hostile or calm target. No decision uses it yet (Test 99).

- **On fire (T-1.27):** `fire_reaction` (before the stairs-retreat and Phase A) reads `is_on_fire`: step into adjacent deep water, else move away from `[HAZARD: fire]` cells, else do nothing (let it burn out); at most `FIRE_REACTION_MAX` (10) consecutive turns.
- **Burrowing Claws (T-1.26):** `claws_toggle_action` (Phase A, before autolevel) switches `CommandToggleBurrowingClaws` OFF when `is_town_zone` (R7) and ON elsewhere, at most once per `CLAWS_TOGGLE_GAP` (25) turns. The claws are not in a wired family: the LLM and fallbacks never see the toggle. Water/sector traversal targets are committed intents: `sector_target_ok` writes a target off after `SECTOR_STALL_LIMIT` (14) turns without a new closest distance (the "nearest cell" chase is tracked per zone and ends in `SECTOR_GIVEUP`).
- **Throwing (BACKLOG B24, HANDOFF issue 115, Test 137):** `thrown_weapon` (the first thrown weapon the engine's AI would throw: `id`, `name`, `blueprint`, `in_thrown_slot`; or `null`) and `last_throw` (the result of the last `THROW_ITEM`: `seq`, `ok`, `reason`, `weapon`, `x`, `y`; or `null`). Python (`throw_option`, `note_throw_result`) offers `THROW_ITEM@x,y` in the combat menu when a hostile is in view at distance 2 to 7 with a clear line and nothing adjacent, runs the same line-of-fire guardrail as `FIRE_MISSILE`, and pauses the option for 200 turns after two refusals in a row.
- **Burrowing:** `last_burrow` (result of the last `ATTACK_WALL` swing: `seq`, `dir`, `name`, `x`, `y`, `has_hp`, `hp_before`, `hp_after`, `max_hp`, `destroyed`, or `null`). Python keeps swinging while the target loses HP, writes it off (400 turns) after 3 swings with no damage or at once if it has no HP, and `guard_blocked_burrow` swaps in another breakable obstacle, a free move, or a pass (T-1.19).
- **Exploration:** `frontier_checked`, `frontier_cells`, `frontier_targets` (T-1.18: explored walkable cells touching unexplored cells that the engine pathfinder can route to, up to 3 per quadrant NW/NE/SW/SE, never cells the player already stood on; computed only while autoexplore is stuck or the zone is engine-explored: `q`, `x`, `y`, `ux`, `uy`, `dist`), `zone_fully_explored`, `autoexplore_stuck`, `unexplored_cells`, `unexplored_centroid_x/y`,
  `nearest_unexplored_x/y/dist`, `reachable_edges` (string of N/S/E/W)
- **Move feedback:** `last_move_failed`, `last_failed_dir` (a direction, or `PATH_BLOCKED`)
- **Survival:** `hunger_level`, `is_hungry`, `is_famished`, `has_food`, `food_count`, `food_items`, `corpses_nearby`,

- **Inventory (T-1.44):** `inventory` (every carried or worn item except natural weapons: `id`, `blueprint`, `name`, `count`, `weight` (the stack's total), `equipped`, `identified`), `carry_weight`, `max_carry_weight` and `last_inventory_action` (`seq`, `kind` equip or drop, `ok` as `id|name`, `failed` as `id:reason`, `zone`, `x`, `y`). Python `choose_inventory_action` (Phase A step 3C, after loot) equips one clear upgrade per turn (never an unidentified item), then drops whitelisted junk (armor, shields, melee weapons, scrap, corpses; firearms and bows are kept as trade assets, Test 93) in batches of 5; `note_inventory_action` stops retrying an id the game refused twice and writes every drop to `memory/item_drops.jsonl` with the zone and cell where it was left. Everything else is deferred to a later stage.
- **Loot (T-1.34):** `loot_sources` (up to 8 within 14 tiles: `kind` `item` or `chest`, `name`, `tx`, `ty`, `dist`; unowned only, empty outside settlements; an item is one the engine would autoget (`CanAutoget`, `ShouldAutoget`), not a corpse, within the weight guard; a chest is `ShouldAutoexploreAsChest` with contents and no `Brain`/`Mimic`) and `last_loot` (`seq`, `kind`, `name`, `count`, `left`). ## 7. Failure memory (Chronicler)

On death: C# writes `death.json` (cause, killer, level, zone). Python gives the Chronicler the last few actions and asks
the LLM for a <=20-word aphorism, saved to `memory/ancestral_wisdom.json` and prepended (last 4) to Phase B prompts.
Limits: lessons carry no state context, only 4 are used, and LLM timeouts store a generic placeholder. See HANDOFF.
