- **Roadmap task:** 1.1 (Phase 1, Stop the hangs)

## Goal
Every command passed to `ExecuteCommand` costs the player a turn. If a command returns without spending energy, `Prefix`
spends one for it and logs that it did.

## Context
HANDOFF issue 1 `[verified in code @c50b3c2]`: several commands `return;` without spending energy: the three refusals in the
`FIRE_MISSILE` branch (companion in cell, companion in line of fire, no line of sight) and the swimming guards in `MAKE_CAMP`
and `COOK_MEAL`. No turn passes, so the game re-exports an identical state and Python re-sends the same action. Python's loop
breaker exempts combat actions, so a repeated `FIRE_MISSILE` refusal is never broken. Not yet reproduced in game
(`[unverified]` that this caused the level 5 hang; it is only one of three hypotheses).

## Approach (suggested)
In `Prefix`, around the existing `ExecuteCommand(player, action)` call:

```csharp
int energyBefore = player.Energy?.Value ?? 0;
ExecuteCommand(player, action);
bool exempt = string.Equals(action?.Trim(), "ACTIVATE_SPRINT", StringComparison.OrdinalIgnoreCase);
if (!exempt && player.Energy != null && player.Energy.Value >= energyBefore)
{
    UnityEngine.Debug.LogWarning($"[QudAI EnergyGuard] '{action}' spent no energy; passing a turn.");
    player.UseEnergy(1000, "Pass");
}
```

Decide and note in *Result* whether `ACTIVATE_SPRINT` is intentionally free. Python never sends it twice in a row, which is why it is exempted here.
Check that zone changes (stairs, border crossing) do not trip a false guard event: watch the log during a transition.
