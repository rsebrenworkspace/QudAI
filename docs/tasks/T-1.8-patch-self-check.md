# T-1.8: Harmony startup self-check

- **Roadmap task:** 1.8 (Phase 1, Stop the hangs)
- **Branch:** `task/1.8-patch-self-check`
- **Owner:** Antigravity implements, Claude reviews (second usage benchmark: compare cost with T-1.1)
- **Status:** Not started

## Goal
At game launch the log states, once, which of the mod's Harmony patches actually applied, and names any that did not.
A patch that silently failed to apply can no longer hide.

## Context
HANDOFF "Level 5 investigation", hypothesis 1 `[unverified]`: a patch in the level-up flow (`Popup.ShowYesNo`, `Popup.PickOption`)
may never have applied. Harmony skips a patch if prefix parameter names do not match the target or if the target method has
several overloads and the attribute is ambiguous. `dry_run.py` cannot detect this. The 2026-09-19 `Player.log` supplied for
review contained no `[QudAI ...]` lines at all.

The mod has **10** patches (ARCHITECTURE section 4): `XRLCore.PlayerTurn`, `GameObject.Die`, `PickDirection.ShowPicker`,
`PickItem.ShowPickerInternal`, `Popup.PickGameObject`, `PickTarget.ShowPicker`, `PickTarget.ShowFieldPicker`,
`Popup.ShowYesNo`, `Popup.ShowYesNoCancel`, `Popup.PickOption`.

## Files you may edit
- `mod/QudAIBrain/AIBrainPart.cs`: add one static method and call it once from `Prefix`.
- `docs/ARCHITECTURE.md` (section 4 note), `docs/HANDOFF.md`.

## Constraints
- AGENTS.md **R1**: use the Harmony API to ask the engine what is patched; do not guess.
- The check must never throw or block (wrap in try/catch; log only).
- Do not change any existing patch in this task, even if the check shows one is broken. Record the finding and open a new card.
- Keep the list of expected targets in **one** place in code. `tools/check_docs.py` already compares code patches to docs; the runtime check compares code patches to what Harmony actually applied.

## Approach (suggested; verify the Harmony API names compile in this Qud build)
1. In `Prefix`, on the first call only (`static bool announced`), log `[QudAI] PlayerTurn patch ACTIVE`.
   (If the `PlayerTurn` patch itself failed, `Prefix` never runs, and the **absence** of this line is the signal. Say so in the log docs.)
2. Build the expected set by reflection over types in the executing assembly that carry `[HarmonyPatch]`, reading the target type and method name.
   (If that is awkward, a hard-coded array of the 10 `Type.Method` strings is acceptable, but then `check_docs.py` must stay in sync.)
3. Compare with `Harmony.GetAllPatchedMethods()`, filtered to methods whose patch info contains a prefix/postfix whose declaring type is in namespace `QudAIBrain`.
4. Log one line per patched target: `[QudAI] Patched: Popup.ShowYesNo`, and `[QudAI] PATCH MISSING: Popup.PickOption` for any expected target not found. End with `[QudAI] Patch check: 9/10 applied`.

## Acceptance criteria
- [ ] Compiles; braces check passes.
- [ ] With all patches healthy, `Player.log` shows the ACTIVE line once and `10/10 applied`.
- [ ] **Negative test:** temporarily break one patch (for example rename a prefix parameter in `AIPickOptionPatch`), launch, and confirm the log reports it missing. Revert the break before committing.
- [ ] The check does not throw if `Harmony` returns nothing, and does not run more than once per launch.
- [ ] HANDOFF "Needs a human" updated with how to read the result.
